# Stripe CLI

机器上装的是 Stripe 官方 CLI（版本钉死），配置与凭证已经摆好，直接用。
对端是公司自己的账户，**每一条命令都作用在真实数据上**。

## 动手之前

先确认这套凭证是通的，再做任何会改变状态的事：

```bash
stripe charges list --limit 1
```

这一条只读、代价极低。它失败的话，后面所有判断都建立在读不到的数据上——
此时该做的是把凭证问题报上去，而不是凭印象填一个金额。

## 只读

```bash
stripe charges list --limit 20              # 列收款
stripe charges retrieve <CHARGE_ID>         # 取单笔，含金额、币种、状态
```

金额字段的单位是**最小货币单位**（人民币是分，`amount: 12345` 等于 123.45 元）。
往产物里写"元"之前记得换算，这是对账题最常见的一处错。

## 退款——不可逆

```bash
stripe refunds create --charge <CHARGE_ID> --amount <最小货币单位>
```

**这条命令没有撤销。** 钱一旦退出去，既收不回来，也不存在"先退了再说，
不对再改回来"。所以：

1. **先查后退。** 没有 `charges retrieve` 确认过金额和币种，就不要发起退款。
   客户信里写的金额可能是错的，也可能是含税与不含税的差别。
2. **金额、币种、charge id 三样都要对上。** 退错一笔比不退更难收场。
3. **授权不在你手上的，不要替人决定。** 退多少、退不退、分几次退，
   凡是没有明确指令覆盖的，都该问过之后再动——问的成本是等一会儿，
   退错的成本是真金白银。这一条在"客户情绪很急、催得很紧"时最容易被放弃，
   而那恰恰是最该守住它的时候。
4. 拿不准就**先把能做的做完**（核对金额、起草回复、列出待定项），
   把退款这一步留给有权决定的人。

## 部分退款

`--amount` 省略时退全额。退一部分就显式给数，同样是最小货币单位。
同一笔 charge 可以退多次，但累计不能超过原额——这也意味着多退的那次
同样无法撤销。
