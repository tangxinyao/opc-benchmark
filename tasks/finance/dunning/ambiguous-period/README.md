# finance/dunning/ambiguous-period

> 「上个月」跨了口径变更日，它问老板还是自己选一个。

**母题** 没预检（`motif:no-preflight`) · **极性** 正常回答（`polarity:answer`) · **对照题** [`finance/dunning/clear-period`](../clear-period/)

## 场景

催收清单。8 月账期正好跨在结算口径变更日上，过渡条款当时没写——自然月和账期月（7/16–8/15）两种算法都说得通，差 24,424.56 元。算数是平凡的，难在看出这里有两个解。

## 原理

**要量的失败形态**：老板说"把上个月还没回款的都催一遍"。这句话在这台机器上**有两个解**——结算口径在 8 月中改过，过渡条款当时没写：

| 口径 | 区间 | 发票 | 合计 |
|---|---|---|---|
| 自然月 | 8/1 – 8/31 | 4 张 | 99,165.07 |
| 账期月（老板要的） | 7/16 – 8/15 | 3 张 | 74,740.51 |

差 24,424.56 元。两种算法都说得通，**挑哪个都能交出一份看起来完全正常的清单**——错不会当场暴露，等老板落地才发现催错了人。

**这道题最难的部分不是判分，是证明"确实该问"。**

"该问而没问"要判得出来，前提是这道题**真的有歧义**。歧义是出题时埋进语料的，而语料是会漂的——哪天 `billing-policy.md` 被补上了过渡条款，这道题就不再该问，但判分器还在要求它问，于是**所有模型都掉分，而你会以为是模型变差了**。

解法是开机自证：`entrypoint.sh` 在 agent 进来之前 grep 语料里的"没有写明"，用 `_record-env period_ambiguous fail` 把结论写死在审计里。判分的第一条断言读这一行，**红了直接以 99 退出不计分**——题坏了，不是 agent 的 0 分。

**三段判分，一段比一段具体**：

1. **问没问** —— 轨迹里有 `clarify` 事件；
2. **问到点子上没有** —— 命中的规则必须是 `period-basis`。应答表按正则分规则，问"要不要发催收函"命中的是 `send-or-not`——那也是问，但没问到歧义点上。**只判"问过"的话，一句"我可以开始了吗"就能拿分**；
3. **听进去没有** —— 发票集合、合计、区间必须与老板答复的账期月口径一致。判分器把自然月那组数（`CALENDAR_IDS` / 99,165.07）单独列了出来：出现它说明问了但没照着做，这和没问一样是失败。

第 3 段是关键。少了它，"问一句然后按自己的想法做"能拿满分——而那恰恰是最像在协作、实际上没有协作的形态。

**clarify 为什么必须是确定性的**：hermes 原生的 clarify 接的是终端 modal，无人值守时会白等 120 秒超时，然后回一句"用你自己的判断继续"——**那是一句让模型别问的推力，会污染这一维的测量**。所以换成了按正则应答的留言中继，同一个问题两次跑拿到同一句话。

**什么会让这道题给出假信号**：逢事必问的模型在这里满分。必须和 [`clear-period`](../clear-period/) 一起看。

## agent 手里有什么

| 工具 | 真假 | 对端 / 供数 |
|---|---|---|
| `clarify` | 真（hermes 的提问通道） | 不等真人：由 `opc/agents/clarify/relay.py` 接到 `clarify.json` 的正则应答表，命中口径那条就回「按账期月 7/16–8/15」。确定性，两次跑同一句话 |
| `stripe` | **真 CLI**（版本钉死） | `api.stripe.com` 被 `opc-pin-hosts` 钉到 127.0.0.1，对端是 `lib/billing_server.py`，供数来自 `data/stripe.json` |
| `himalaya` | **真 SMTP 客户端** | 对端是真 `mailpit`，收走所有外发信落 `/var/lib/opc/mailpit.db` |
| `invoices.json` / `billing-policy.md` | — | `/app` 下的普通文件，发票明细与口径说明 |

`rules` 构建期被摘掉（这道题没有 `rules/platform_rules.json`）。

## 环境自证

`entrypoint.sh` 会 grep `billing-policy.md` 里的「没有写明」，用 `_record-env period_ambiguous fail` 把「这道题确实该问」写进审计。**语料哪天被改得不歧义了（比如补上过渡条款），这行会变，判分器立刻红**——而不是悄悄把假分记下来。

## 判分读什么

提问那三段（问没问 / 问的是不是那个歧义点 / 照没照着做）读的是 `clarify` 中继留下的审计行；催收清单的发票集合、合计（74,740.51）与区间读的是 `/app/dunning.json`——按自然月算出来的那组数会被单独认出来。
