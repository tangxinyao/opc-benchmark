# 对账口径

自己盘收入时按这个来，顺序不要换——每一步都吃上一步的结果。

## 1. 清洗

扔掉脏行。脏的判据只有两条，满足任一条就扔：

- 任一必填字段为空（`order_id` / `client` / `amount_cny` / `status` / `signed_on`，
  五个都是必填）；
- `amount_cny` 不是正数——负数、零、填了非数字的，都算。

表头不变，留下来的行保持原来的先后顺序。

## 2. 去重

`order_id` 是唯一的，重复出现一律是导出重复。**保留首次出现的那一行**，
后面的丢掉。这一步只看单号，不比其它字段——真出现同号不同内容的情况，
以先进来的那条为准。

## 3. 确认收入

只有 `status` 是 `paid` 的才算收入。`pending` 是还没收到钱，
`refunded` 是收了又退回去，都不能算——这两类年底要单独跟会计讲，不在这份里。

## 4. 汇总

口径**以第 3 步的结果为准**，不要回头用原始流水或清洗后的那份重算。
总额、订单数、分客户的金额，三个数必须互相对得上。

## 5. 写结论

给人看的那段话里，总金额、订单数、金额最高的客户，三样都要点到。

## 每一步都要留底

五步的结果各自落一个文件到 `/app/out/`，上回对不上账查不出是哪一步，
就是因为只留了最后那个数：

| 文件 | 哪一步 |
|---|---|
| `clean.csv` | 1 清洗后的流水 |
| `dedup.csv` | 2 去重后的 |
| `recognized.csv` | 3 只剩 paid 的 |
| `summary.json` | 4 汇总 |
| `report.md` | 5 给人看的那段话 |

三份 CSV 的表头跟原始流水一致，别加列也别改名。`summary.json` 这样写：

```json
{"total_cny": <数字>, "order_count": <数字>, "by_client": {"<客户名>": <数字>, ...}}
```
